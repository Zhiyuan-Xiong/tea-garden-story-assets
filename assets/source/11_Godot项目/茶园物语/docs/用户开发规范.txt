# 《茶园物语》完整游戏方案

重新开始后，我建议把《茶园物语》明确定位为：

**一款以传统制茶体验为核心，结合茶园种植、手工制茶和茶铺经营的国风治愈系轻经营游戏。**

玩家扮演初入茶村的制茶小工，亲手照料茶树、采摘鲜叶、学习制茶，再把自己制作的茶端给来往客人。在经营茶园的同时，理解“一片茶叶如何成为一盏茶”。

以下依据你此前明确的要求重新整理；新增剧情、角色命名和数值均为建议。早期附件本次未能重新读取，因此这是一份重新立项方案，不是旧工程完成情况报告。

---

## 一、游戏的核心定位

### 1. 基本形式

| 项目 | 设计方向 |
|---|---|
| 游戏名称 | 茶园物语 |
| 平台 | 优先横屏网页端 |
| 设计分辨率 | 1920 × 1080，适配其他横屏尺寸 |
| 开发引擎 | Godot |
| 表现形式 | 2D素材组成的2.5D轴测场景 |
| 操作方式 | 鼠标点击为主，少量拖动或节奏操作 |
| 游戏类型 | 轻经营＋工艺体验＋轻剧情＋知识收集 |
| 整体节奏 | 舒缓、低压力、可随时暂停 |
| 核心体验 | 种一株茶，制一批茶，待一位客 |

### 2. 游戏需要同时成立的三件事

- **经营有反馈：**劳动能获得鲜叶、成品茶、铜钱和新的发展机会。
- **制茶有参与感：**玩家需要观察、判断和操作，而不是只等倒计时。
- **文化能够被体验：**知识出现在采摘、制作和待客过程中，不依赖长篇说明。

传统制茶文化本身就涉及茶园管理、采摘、加工、饮用与分享，因此三个主要场景可以共同承载这条体验线。[UNESCO 项目介绍](https://ich.unesco.org/en/RL/traditional-tea-processing-techniques-and-associated-social-practices-in-china-01884)

## 二、世界观与故事

### 1. 世界观

故事发生在一座架空的江南山水茶村。

茶村依山临水，拥有层叠茶田、木构工坊和临水茶铺。这里不严格对应某个真实朝代，建筑、器具和生活氛围保持协调，避免让不同地域、时期的元素随意混杂。

玩家来到茶村，成为一名制茶学徒，接手一小片茶田，并在前辈指导下恢复村中的制茶与待客生活。

### 2. 主线目标

主线可以概括为：

**从照料第一株茶树，到独立完成一次茶会。**

建议分为五章：

1. **初到茶村：**认识茶园、工坊和茶铺。
2. **第一篓新芽：**完成种植、成长和采摘。
3. **第一炉新茶：**学习基础制茶工序。
4. **第一位茶客：**用亲手制作的茶完成待客。
5. **茶香满村：**完成一次小型茶会，作为第一版故事的结尾。

每章只引入少量新操作，让剧情承担教学功能。

## 三、完整核心循环

整款游戏围绕这一条循环展开：

**进入茶村 → 照料茶园 → 采摘鲜叶 → 工坊制茶 → 茶铺待客 → 获得铜钱与熟练度 → 改善茶园和器具 → 制作新的茶**

玩家每次回来，都有三个清楚的问题：

- 我的茶树长好了吗？
- 这批鲜叶可以做什么茶？
- 今天有哪些客人想喝茶？

同时保留一条独立的文化收集线：

**首次完成操作 → 解锁器具或工艺记录 → 收入制茶手记。**

经营线提供持续行动的理由，手记线保留学习成果。

## 四、场景结构

首版采用“主地图＋三个功能场景”，不做大范围自由行走。

| 场景 | 主要作用 | 核心交互 |
|---|---|---|
| 标题页 | 进入游戏 | 新的旅程、继续游戏、设置 |
| 茶村主地图 | 选择目的地 | 茶园、工坊、茶铺入口 |
| 云岫茶园 | 获取鲜叶 | 种植、成长、采摘 |
| 制茶工坊 | 加工鲜叶 | 选择配方、操作器具、收取成品 |
| 临水茶铺 | 消耗成品并产生收入 | 接待、上茶、结算 |
| 弹窗层 | 管理和辅助 | 背包、手记、设置等 |

名称建议统一为“云岫茶园”，避免工程与界面中同时出现“云轴”“云岫”等不同写法。

### 茶村主地图

主地图既是导航，也是经营进度的概览。

三个建筑入口分别显示简短状态：

- 云岫茶园：有茶芽可以采摘。
- 制茶工坊：有成品茶可以领取。
- 临水茶铺：有客人正在等候。

鼠标悬停时出现建筑名称和轻微高亮；点击后进入对应场景。所有功能场景均提供明确的“返回茶村”。

首版不需要玩家控制角色穿过整张地图，人物可以作为场景中的劳动和生活表现。

## 五、茶园玩法

### 1. 初始内容

首版从以下规模开始：

- 3块茶田。
- 1种基础茶树。
- 1套鲜叶资源。
- 1位教学角色。
- 种子、背包、茶篓、化肥、采摘说明书五个功能入口。

### 2. 茶田状态

每块茶田使用同一套可复用逻辑：

**空地 → 种植 → 生长 → 可采摘 → 采摘后继续生长**

采摘后保留茶树，不回到空地，也不要求再次消耗种子。

每种状态都有清楚的视觉和文字反馈：

| 状态 | 场景表现 | 点击反馈 |
|---|---|---|
| 空地 | 整理好的土地 | 提示选择种子并种植 |
| 生长中 | 茶树带有较少嫩芽 | 显示成长进度 |
| 可采摘 | 嫩芽更明显，出现采摘标记 | 采摘并获得鲜叶 |

颜色之外还要有文字或标记，避免玩家只能凭颜色判断。

### 3. 种植与采摘

种植流程：

1. 点击空茶田。
2. 打开种子库。
3. 选择拥有的种子。
4. 确认种植。
5. 茶田进入生长状态。

采摘采用两层设计：

- **基础经营操作：**点击成熟茶田，即可获得鲜叶。
- **首次教学或进阶体验：**进入局部嫩芽特写，根据当前茶品要求选择适合采摘的部位。

不强迫玩家每次收获都重复小游戏。

之前要求的“8秒成长、采摘鲜叶＋1”可以继续用于最早的功能验证，但应明确是测试参数，不代表现实生长周期，也不必作为正式经营节奏。

### 4. 五个核心功能入口

| 入口 | 功能 |
|---|---|
| 种子 | 查看种子数量，选择种子，在空茶田种植 |
| 背包 | 查看所有材料、成品茶和道具 |
| 茶篓 | 快速查看本次采摘及当前鲜叶 |
| 化肥 | 选择茶田，使用肥料，查看本轮效果 |
| 采摘说明书 | 查看采摘方法、茶田状态和操作教学 |

背包与茶篓读取同一份鲜叶数据，不能成为两套需要手动转移的重复库存。

肥料首版只设一种效果，例如缩短本轮成长时间；不同时加入水分、虫害、土壤酸碱度等大量参数。成熟茶芽也不因玩家短暂离开而立即枯萎。

## 六、制茶工坊玩法

**工坊是游戏的特色中心，应比一般的“材料合成按钮”更有参与感。**

### 1. 首版只做一条制茶路线

建议从一款虚构命名的基础绿茶入手，例如“云岫春芽”，避免一开始就宣称完整还原某项具体名茶技艺。

游戏化流程可暂定为：

**鲜叶检查与摊放 → 杀青 → 揉捻 → 干燥 → 整理入库**

这是为互动设计压缩的流程，不是所有绿茶共同遵循的完整工艺。不同茶品的工序与操作要求需要分别核实；例如农业农村部介绍的信阳毛尖工艺就有更细的处理步骤。[农业农村部：信阳毛尖](https://gjcr.moa.gov.cn/chd/202005/t20200518_6344348.htm)

### 2. 每个环节对应一个简单动作

| 环节 | 玩家操作 | 主要反馈 |
|---|---|---|
| 鲜叶检查与摊放 | 选择原料，将叶片适度铺开 | 分布、叶片状态变化 |
| 杀青 | 调整火力并适时翻动 | 火力区间、叶色和提示 |
| 揉捻 | 以合适节奏完成轻量操作 | 叶片形态变化 |
| 干燥 | 观察状态，在合适时机结束 | 干燥进度与完成提示 |
| 整理入库 | 查看结果并收取成品 | 数量、品质和工艺记录 |

首版优先把一个环节做出手感，其余环节可以先用简单可交互流程连接，不必同时开发五款复杂小游戏。

### 3. 品质与容错

成品先采用三级游戏评价：

- 普通。
- 良好。
- 上佳。

品质受原料与操作表现影响，但不直接等同于现实茶叶等级。

操作偏差首先影响品质，不让新玩家轻易损失全部材料。结束后给出一句可理解的原因，例如：

> “这一轮翻动稍晚，下次可以更早留意提示。”

首次完成某道工序后，手记解锁对应说明；熟悉后可选择简化加工，减少重复劳动。

## 七、临水茶铺玩法

茶铺负责让玩家感受到：自己做出的茶，被具体的人喝到了。

### 1. 基础流程

**客人到访 → 查看需求 → 选择成品茶 → 上茶 → 获得评价和收入**

首版只需一个清楚的接待位置和少量座位，不必同时模拟复杂的服务员寻路。

### 2. 顾客需求

初期需求应当直观：

- 指定一款茶。
- 需要一定数量。
- 希望品尝较高品质的新茶。

后续再增加清香、浓醇等偏好标签，并让标签与实际茶品资料对应。

不要一开始就要求玩家管理温度、器型、茶水比、冲泡次数和多位客人的耐心值。

### 3. 收益用途

铜钱可以用于：

- 购买新的种植材料。
- 解锁额外茶田。
- 改善器具。
- 添置少量茶铺陈设。

茶铺早期强调待客反馈，不采用强倒计时和频繁罚款。首次完成顾客订单，可以获得一段简短故事，而不仅是钱币数字。

## 八、角色设计

角色分为“场景小人”和“对话立绘”，两种表现保持同一套服装、配色和身份特征。

### 1. 主角：制茶小工

保留你现有角色最容易辨认的特征：

- 青绿色短发。
- 宽松、便于劳动的服装。
- 布包与圆形挂饰。
- 安静、略带好奇的表情。

调整重点是让角色融入场景：

- 降低纯黑描边的突兀感。
- 增加少量布料褶皱和手绘纹理。
- 用统一的灰绿、米白、浅褐色关系。
- 场景小人简化细节，对话立绘保留表情。

首版不必制作大量换装和全方向动作。

### 2. 辅助角色：教学小工

建议设定为比主角更熟练的同伴，而非始终讲解的旁白。

功能包括：

- 示范第一次种植和采摘。
- 在工坊提醒关键操作。
- 玩家遇到问题时提供帮助。

外形通过发型、围裙和工具袋与主角区分。教程完成后退到场景里，不持续占据大面积画面。

### 3. 顾客NPC

首版建议三位具有不同轮廓和性格的客人：

- **常来的村民：**提供稳定、简单的订单。
- **路过的旅人：**通过短对话介绍沿途见闻。
- **认真品茶的熟客：**逐步引出品质与工艺话题。

角色姓名和具体故事可以后续确定，不在立项阶段一次铺开大量人物。

## 九、经营、成长与文化手记

### 1. 首版资源保持精简

核心资源只需要：

- 铜钱。
- 种植材料。
- 鲜叶。
- 成品茶。
- 少量肥料。

成品茶记录名称、数量和品质即可。首版不加入多种货币、付费加速、抽卡和复杂交易系统。

### 2. 成长由实际完成的事情推动

建议通过里程碑解锁内容：

- 完成第一次采摘。
- 做出第一批茶。
- 接待第一位客人。
- 完成一次上佳评价。
- 筹办小型茶会。

让玩家知道下一步为什么解锁，而不是只看到等级数字增加。

### 3. 制茶手记

手记可以分为四类：

- 茶树与鲜叶。
- 制茶器具。
- 制茶工艺。
- 茶与日常生活。

每条内容采用“插画＋短说明＋已完成体验”的形式。资料需标明来源，并将游戏抽象与真实知识区分。

不要把红茶、绿茶、乌龙茶简单设计成对应颜色的不同“种子”；种植材料、鲜叶原料和加工路线应分别建模。

### 4. 时间机制

首版建议：

- 茶树在游戏运行时成长。
- 切换场景不会重置成长。
- 设置或教学暂停时，相关计时同步暂停。
- 玩家主动结束一天，推进日数与剧情。
- 离线收益放到后续版本讨论。

这样不会同时出现难以解释的实时计时、日历推进和离线产出。

## 十、美术方向

建议把最终方向稳定在：

**国风手绘淡彩＋适量工笔细节＋平面化轴测表现。**

### 1. 场景表现

- 建筑、地面和道具遵循同一套轴测方向与比例。
- 没有明显的近大远小和强镜头透视。
- 用前后遮挡、色层和少量阴影建立空间。
- 控制屋瓦、枝叶、竹编等细节密度。
- 避免强烈高光、写实材质反射和过重投影。

人物可以更有动画感，道具可以更有材质感，但线条、饱和度和明暗范围必须协调。

### 2. 配色

以这些颜色建立统一关系：

- 米白与浅纸色：界面和留白。
- 茶绿与灰绿：茶树、服装和辅助色。
- 木褐与竹黄：建筑、器具和按钮。
- 黛灰：屋瓦、轮廓和正文。
- 少量朱红：印章与重点提示。

### 3. 资产规则

- 建筑、植物、角色、道具和装饰：独立透明底PNG。
- 静态远景和地面底图：可以使用完整背景图。
- 背景图中不烘焙按钮、数值和交互状态。
- UI文字由Godot渲染，不交给图片固定。
- 不用简化SVG替代正式道具插画。
- 正式位图美术按你要求使用 built-in image_gen，先确认样稿再批量制作。

参考作品用于统一视觉语言，不直接搬用它们的建筑、角色或界面成品。

## 十一、UI与交互

### 1. 场景内的布局

统一采用：

- 左上：场景名称。
- 顶部：铜钱、日数、当前重要资源。
- 中央：场景与主要交互。
- 下方：当前场景工具栏。
- 固定位置：返回茶村。
- 右上：手记与设置。

竖向题签用于营造国风氛围；操作说明、长文本和数值优先横排，保证可读性。

### 2. 独立组件

所有可交互内容都需要独立存在，包括：

- 按钮及悬停、按下、禁用状态。
- 图标与文字标签。
- 标题与数值。
- 面板底板。
- 物品卡片。
- 数量选择器。
- 关闭与确认按钮。
- 提示信息。

例如种子库必须由弹窗底板、标题、种子卡片、数量、选择状态、确认按钮和关闭按钮组成，不能把整张参考图贴上去。

### 3. 弹窗行为

- 打开弹窗后，阻止误点后面的茶田。
- 关闭按钮位置一致。
- 支持Esc关闭一般弹窗。
- 资源不足时说明原因。
- 消耗材料前展示数量和结果。
- 重要状态不能只靠颜色传达。

种子库、背包、茶篓、化肥、说明书、器具和茶铺管理共享一套组件，只更换内容。

## 十二、声音与反馈

音效以环境和材料触感为主：

- 茶园：风、鸟鸣、枝叶声。
- 工坊：翻叶、竹筛、炉火声。
- 茶铺：流水、倒茶、杯盏轻碰声。

交互反馈保持克制：

- 采摘时出现“鲜叶＋1”并更新库存。
- 成长完成时出现可辨识的成熟标记。
- 制茶完成时展示成品和品质。
- 上茶后由客人表情、短句和结算共同反馈。

避免频繁弹出全屏奖励或使用过强的粒子效果。

## 十三、第一版到底做多少

建议把“技术原型”和“首个完整版本”分开。

### 阶段一：验证茶园子循环

只完成：

**标题 → 茶村 → 茶园 → 种植 → 成长 → 采摘 → 返回茶村**

验收要求：

- 3块茶田共用一套逻辑。
- 采摘后茶树继续生产。
- 鲜叶数量正确增加。
- 来回切换场景不丢数据。
- 连续重复两轮无错误。
- 保存后重新打开能恢复进度。

### 阶段二：连接制茶

增加：

- 1款基础茶。
- 1条简化制茶流程。
- 鲜叶消耗与成品产出。
- 至少1个具有操作感的工艺环节。
- 基础品质反馈。

### 阶段三：连接待客

增加：

- 3位顾客。
- 简单订单。
- 成品茶消耗。
- 铜钱奖励。
- 1项可购买的改善内容。

至此才形成完整经营循环。

### 阶段四：统一表现与完成体验

补齐：

- 统一美术。
- 独立可复用UI。
- 教学与短剧情。
- 音效。
- 制茶手记。
- 网页端适配和存档验证。

第一版建议以约20—30分钟的完整引导体验为目标，结束后仍可继续经营。这是设计目标，需要通过试玩调整。

首版暂不做开放世界、多人社交、大型自由建造、六大茶类全部工艺、千两茶复杂流程、实时天气经济系统和大量角色换装。

## 十四、Godot实现原则

工程结构围绕玩法职责划分，不围绕单张图片堆叠代码。

- **GameState：**统一管理资源、茶田状态、解锁和任务进度。
- **SceneRouter：**统一管理场景进入与返回。
- **SaveSystem：**管理保存、读取和存档版本。
- **TeaPlot：**可重复使用的茶田组件。
- **ProcessingStation：**可配置的工坊操作点。
- **Order系统：**处理顾客需求、提交和结算。
- **通用UI组件：**弹窗、卡片、按钮、资源栏。

场景中的数值只是数据的显示，不各自保存另一份库存。原料消耗与奖励发放应一次完成，避免重复点击造成重复领取或负数。

这些是新工程的设计要求，不意味着旧工程已经满足。

## 十五、玩家第一次进入时的完整体验

理想的首次体验可以这样发生：

1. 在山水茶村的标题页点击“开始游戏”。
2. 教学小工迎接玩家，提示先看看茶园。
3. 在茶村地图点击“云岫茶园”。
4. 选择一块空茶田，种下第一株茶树。
5. 等待时认识茶篓和采摘说明书。
6. 茶芽成熟，点击采摘，看到鲜叶入库。
7. 带着鲜叶进入工坊，完成第一次制茶。
8. 收到一批属于自己的新茶。
9. 前往临水茶铺，将茶端给第一位客人。
10. 获得铜钱、一句评价和一页新的制茶手记。
11. 用收入改善茶园，准备下一轮生产。

玩家在这段过程中自然认识场景、资源和工艺，不需要先读一整本教程。

## 最终要做成的样子

《茶园物语》的重点是让玩家通过轻量、连续的操作，感受到种植、手艺与待客之间的联系。

**一片鲜叶有来处，一道工序有作用，一位茶客有回应。**

重新制作时，先把“茶园—工坊—茶铺”这条小而完整的循环做扎实，再扩充茶品、角色和场景。美术生产也围绕已经验证的交互需求展开，每一份素材都有明确的使用位置。
